# localhost usbip / VHCI での検証結果

## 検証環境

- 検証対象: `px4-userland` Stable v0.1.3 x86_64 glibc 配布アーカイブ（source ref `639e65f`、SHA-256: `5eabfa041c1d61230b31c0ed370d40f842a741d8523756c826b926f58155269b`）
- ホストハードウェア: Latitude 5300
- OS: AnduinOS（Linux 7.0.0-31-generic、usbip 2.0）
- 使用チューナー: PX-Q3U4 1台（2つのUSB機能）

## 構成手順とデバイス指定

- 専用の network namespace 内で loopback を介して `usbipd` を起動する。
- PX-Q3U4 の2機能を別々の VHCI ポートへ attach する。
- 物理ノードとVHCIノードが同一libusbコンテキスト内で同一シリアルとして二重列挙される。
- 通常列挙時の重複スロットエラー（`INVALID_ARGUMENT`）を回避するため、VHCI側の2ノードを事前オープンし `px4d --fd FD --fd FD` で指定する。

## 検証結果

- 初回BS13_0の30分試験では、受信機2・3・6においてcontinuity error各2件を検出した（判定例外を設けずstrict failとして証跡保持）。
- 再試験（BS15_0）において、60秒gate試験および30分soak試験ともに8受信機すべて合格した。
- BS15_0 30分連続受信実績:
  - 各受信機 20,756,732〜28,864,141パケットを受信
  - 全TSエラー、キュー破棄、USBエラーはすべて0件
- ステータス照会（`px4ctl status`）は30回中30回成功した。
- 内蔵カードリーダーに対する直接APDU送信も30回中30回成功した。
- カーネルエラーの記録は0件であった。
- 試験終了後にTCP 3240ポート、network namespace、VHCIポート、プロセスの残留がないことを確認した。
- 物理USBインターフェースのドライバ未割当状態への復元を確認した。

## 適用範囲と境界

- 検証実績: 同一Linuxホスト内におけるlocalhost/VHCI経由の通信経路、およびFD指定起動。
- 通常列挙時の重複認識はデバイスディスクリプタの破損ではなく、同一コンテキスト内の列挙仕様に起因する。
- 再検証対象: 物理ネットワーク（LAN）を経由するリモートusbip構成、および通信途絶・切断注入試験。
